# 0.1.28 前后端接口与无用代码清理

清理依据为仓库内界面、组合函数、Agent 工具、服务、测试及验收脚本的调用。没有仅凭前端页面不引用就删除工具或后台服务；仓库外的自定义客户端不在可扫描范围内。

## 已移除

| 内容 | 原因与替代方式 |
| --- | --- |
| 前端 `listMessages` | 无调用方，统一使用保留游标信息的 `listMessagePage` |
| 前端 `ApprovalDetail` | 无使用方，审批界面使用 `ApprovalItem` |
| ChatView 的 `onSteer` 解构与 `phaseIndex` | 模板未使用；运行中补充仍由组合函数的发送流程处理 |
| 旧 PPT 预览列表、开发者身份表单等样式 | 对应页面结构已删除 |
| `GET /api/sessions/{sessionId}/runs/{runId}` 与 `getRunInSession` | 无调用方，任务详情统一使用 `GET /api/runs/{runId}`，保留账号归属校验 |
| `GET /api/runs/{runId}/progress` 与 `RunApplicationService.progress` | 无调用方；基本状态使用任务详情/同步接口，读取记录与阶段发现使用 `/api/operations/runs/{runId}/progress` |
| ApiController 的四个局部异常处理器 | 与全局处理器重复，统一由 `ApiExceptionHandler` 返回状态码和错误体 |
| SSE 的 tenantId/userId 查询参数兼容分支 | 登录过滤器统一构造身份，流式请求使用 Bearer 请求头；继续保留事件游标和 Last-Event-ID 重连 |

旧的两个任务查询路由下线后返回404。自定义客户端应按表格迁移，不会静默转到不检查所有权的接口。

## 保留与防止回归

- 保留通知跳转使用的 `getRun`、模型实际连接测试、技能依赖与版本管理、运行时检查、产物与审批等接口；这些均存在调用方。
- 保留 `onSteer` 本体及测试：输入框在任务运行期间发送补充时仍使用它。
- TypeScript 开启 `noUnusedLocals` 和 `noUnusedParameters`，构建时阻止新增未使用局部声明。
- 为下线接口404、主控制器统一错误码、SSE旧身份查询参数不能替代认证头增加回归测试。补齐无映射路由的404处理，避免落入通用500响应。

完整回归和真实数据库、桌面验收结果记录在[性能验证结果](性能验证结果.md)；账号与安全边界见[账号与安全设计](账号与安全设计.md)。
