## 0.1.21 功能与交付验证

- 后端 178 项测试、前端 40 项测试通过。
- 真实 AI 验证 Chat 问答、搜索与网页读取、Plan 保留待执行步骤，以及同会话 Build 执行并读回文件。
- 验证生成中暂停、暂停期间不增加模型调用、跨过原超时时间仍能继续、继续请求幂等。
- 在途 MCP 操作先完成后暂停；继续后没有重复执行。
- 桌面源代码版本与打包版本验证：输入框右侧暂停，同一输入框补充并发送继续，
  重新打开仍显示暂停状态，始终沿用原任务 ID。
- 自定义后端地址在首个页面模块执行前就绪，验证窗口没有先请求默认后端。
- 完整源码包包含文件清单和 SHA-256，解压后验证后端测试/构建与前端测试/构建。
  前端重建复用了本机已安装依赖；源码包本身不包含 node_modules。

可重复验证脚本、运行环境与省 Token 的任务模板见“开发与性能说明”。

## 0.1.22 多模型补充验证

- 后端 188 项、前端 47 项测试通过；模型管理的运行 JAR 与当前源码编译结果逐文件一致。
- 真实 PostgreSQL 迁移恢复两个旧模型配置，保留原选择；创建、编辑、选择和删除相互独立。
- 同一地址的两个模型使用各自 Key，测试未选中的配置没有借用当前模型的 Key。
- 运行中修改配置并切换后，该任务的后续工具调用仍沿用原模型版本；新任务使用新选择。
- 过期编辑返回冲突，其他用户无法选择、编辑或删除该配置。原有真实模型连接与工具调用检测通过。
- 桌面源码与打包界面验证只填 URL、Key、模型名即可新增；保存不切换，输入框选择后重载及
  新桌面进程仍保留列表与选择，删除一项不会删除其他模型。密钥不回显。

## 0.1.23 连接检测与响应恢复

- 后端 195 项、前端 49 项测试通过。
- 保存前以实际流式工具协议验证配置，错误 Key 的新增和编辑均被拒绝，原配置与选择不变。
- 模拟两次 503 后恢复，任务流式返回完整正文；多次成功的工具步骤不拉长下一次失败的退避时间。
- 连续三次失败后持久化暂停，等待期间不再发请求；同一任务继续后恢复并完成。
- 桌面源码及打包版本验证失败原因、重新加载、原任务继续，以及保存前检测失败不落库。
- 真实 MiMo mimo-v2.6-flash 的配置经过保存前校验，再通过完整任务链返回景点常识答案：
  单次验证约 13 秒，正文 452 字符。此记录是一个验证样例，不代表服务始终可用或固定延迟。
