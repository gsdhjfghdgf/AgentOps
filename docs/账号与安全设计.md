# AgentOps 账号与安全设计（0.1.28）

本轮把本地调试身份改为真实账号，并针对可验证的攻击入口增加服务端防护。它是本机桌面 Agent 的安全边界，不是公共多租户云服务或完整的渗透测试结论。

## 账号和旧数据

注册、登录、退出、资料修改、密码修改、登录设备查询与撤销由后端持久化。首个本机账号可以选择接管默认旧身份的数据；后续账号由服务端分配独立身份，不能自行填写其他人的 Tenant/User ID。

注册必须提供本机注册凭据：默认保存在当前系统用户主目录的 `.agentops/registration.key`，只授予文件所有者访问权限。桌面主进程通过受限 IPC 读取，普通网页及子框架不能读取。需要其他部署方式时可由管理员配置 `AGENT_REGISTRATION_KEY_FILE`，并通过可信渠道分发，不在聊天、日志或源码中提供。不要删除凭据文件来重置账号，它不等于密码。

密码使用 Spring Security PBKDF2 哈希，长度 10～128；不保存明文密码。登录使用 32 字节随机凭据，数据库仅保存 SHA-256 摘要；普通登录有效12小时，记住登录30天，最多20个有效设备。修改密码验证旧密码并撤销所有登录。没有实现邮箱验证、邮件找回或管理员角色体系。

桌面端记住登录使用 Electron safeStorage 的系统加密；不能加密时不会降级为明文文件。浏览器仅使用 sessionStorage。HTTP 请求及实时输出都使用 Authorization 头，不在 URL 中携带登录凭据。旧 SSE 身份查询参数和身份头均不能替代认证。

## 防护与对应边界

| 入口 | 本轮防护 |
| --- | --- |
| 身份伪造与越权 | 除健康检查和账号公开入口外默认认证；身份由服务端注入，查询和下载检查对象归属 |
| 编码路径与矩阵参数 | 默认认证全部路由；拒绝分号、重复分隔符、双重编码及编码路径分隔符等歧义路径 |
| 跨站调用、注册抢占 | 精确 CORS 来源、无 Cookie Bearer 认证、本机注册凭据；不以 localhost 或 null Origin 作为注册授权 |
| 暴力登录 | 数据库持久化尝试次数，失败事务不会回滚计数；错误账号和错误密码返回相同登录错误 |
| SQL 注入 | 账号和资源查询使用参数化 SQL；用户名限定格式，会话标题等内容仍作为普通数据保存 |
| XSS 与自动外传 | Markdown 使用白名单清理，去除脚本、表单、SVG、样式注入等；外部图片不自动加载，外链仅允许 HTTP(S) 并隔离打开；HTML 成果在无脚本沙箱内预览 |
| SSRF 与 DNS 重绑定 | 公网工具只允许 HTTP(S)80/443；拒绝本机、私网、元数据及保留地址；逐跳重验并连接已校验的具体 IP，上游代理也接收该 IP |
| 资源耗尽 | JSON 上限256KiB（含分块请求）、上传20MB；IP/账号限流、渲染导出限频、实时连接每账号4条/全局64条，HTTP线程和连接数量有上限 |
| 慢速响应 | 公网响应限制大小，正文读取设置独立截止时间，重定向次数受限 |
| 命令与环境注入 | 命令默认禁用；任务批准不能由联网授权替代；子进程不继承服务密钥或 NODE_OPTIONS、BASH_ENV 等启动钩子，数据处理优先使用专用工具 |
| 恶意资料与提示注入 | 文档、网页、MCP返回和技能明确作为不可信资料；服务端校验工具可见性、模式、参数、身份和授权，损坏的参数JSON拒绝执行 |
| 错误与敏感信息 | 客户端不接收内部堆栈、SQL或凭据；意外错误带可核对编号；密码和登录返回对象的日志表示脱敏 |

主机 `command_run` 仍以操作系统用户权限执行，清理环境不构成系统隔离，已授权的主机命令仍可能访问该系统用户能访问的文件。不可信脚本优先用 `sandbox_run`：虚拟机容器、无网络、无宿主项目挂载、只读根目录、非特权用户、资源限制；不能自动降级到主机执行。显式配置的模型和 MCP 服务是管理员/用户指定的网络目标，不与普通公网搜索使用相同的禁止内网规则。

应用限流不能抵御链路被占满的大流量攻击。对外部署还需 HTTPS 入口、反向代理/WAF、网络访问控制、备份和监控。提示词约束也不能保证识别所有恶意资料，权限与隔离仍是实际边界。

## 验证与依赖

账号、攻击场景与桌面验收使用独立 PostgreSQL 测试库，避免占用正式用户的首个账号。`verify-accounts.mjs` 拒绝直接在8080生产后端运行。专项测试覆盖身份伪造、异常路径、跨用户读取、无注册凭据抢占、恶意URL、代理重定向、子进程环境清理、请求上限和会话撤销。

使用 HTTPS Maven 仓库配置：`mvn -s .mvn/secure-settings.xml verify`。安全补丁采用同系列 Spring Boot 3.5.16；桌面运行时为 Electron 44.10.2，同时更新 DOMPurify 与构建工具。依赖审计的“零公告”只代表对应仓库在检查当时的报告，不能解释为软件没有漏洞。

2026-11-04 的官方 npm 审计：生产依赖0项公告；全量依赖仍有15项中危传递依赖公告，涉及打包工具中的 minimatch、EJS 等，未发现高危或严重项。它们不进入桌面运行包，构建仅处理本仓库受控的文件匹配及模板。npm 建议的强制修复会将打包器降到旧版本，因此没有用降级或不兼容覆盖来隐藏报告。后续需跟进上游兼容修复；本轮不声称全依赖零漏洞，也未完成 Java 全依赖漏洞扫描或外部渗透测试。

参考：[Spring 密码保存](https://docs.spring.io/spring-security/reference/features/authentication/password-storage.html)、[Electron 系统加密](https://www.electronjs.org/docs/latest/api/safe-storage)、[Electron 44.10.2 安全回补](https://releases.electronjs.org/release/v44.10.2)、[Spring Boot 3.5.16 依赖版本](https://docs.spring.io/spring-boot/3.5/appendix/dependency-versions/coordinates.html)。
