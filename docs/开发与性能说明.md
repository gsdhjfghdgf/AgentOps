# AgentOps 0.1.23 开发、性能与源码交付

## 完整源码

前端在 agent-web/src，桌面主进程在 agent-web/electron；后端在
agent-server/src/main/java/com/agentops，数据库迁移在 agent-server/src/main/resources/db/migration。
源码包包含前后端源码、测试、锁文件、配置模板和构建脚本；不含历史数据、密钥、
node_modules、Maven target 和旧安装包。

前端逐文件说明见 agent-web/README.md。后端按职责组织：

| 层 | 目录 | 职责 |
| --- | --- | --- |
| HTTP 展示 | api/web | 接口和响应表示、增量同步 |
| 用户控制 | api/RunControlService | 暂停、补充后继续、幂等控制回执 |
| 事务编排 | coordinator | 状态、检查点、租约、授权与结果提交 |
| 执行 | engine、tool | 模型决策循环与工具派发 |
| 上下文 | context | 提示词、历史窗口和估算，相互独立 |
| 模型 | model | 服务适配、按需工具目录、向量缓存 |
| 数据访问 | persistence | SQL 与持久化边界 |

## 启动与配置

1. 安装 JDK 17、Maven、Node.js 20/22。
2. 准备 PostgreSQL + pgvector 与 Redis，或使用自己的虚拟机服务。
3. 源码包中的 application.yml 用环境变量代替了密码和模型 Key。
   按 .env.example 创建项目根目录 .env，填写自己的值，再加载：

    .\scripts\load-local-env.ps1
    cd agent-server
    mvn spring-boot:run

后端健康检查是 http://127.0.0.1:8080/actuator/health。
再按前端 README 启动页面或桌面应用。Ollama 向量服务由管理员配置，普通用户界面不提供向量模型修改。
聊天模型也可以在界面中填写 URL、Key 和模型名。虚拟机隧道是本机部署方案，不是其他机器的必需步骤。

    # 后端测试及 JAR
    cd agent-server
    mvn verify
    # 前端测试及 Windows 安装包
    cd ..\agent-web
    npm ci
    npm test
    npm run dist

## 这次优化

- 业务接口与 HTTP、SSE 传输拆分。相同身份下同时发出的相同 GET 只进行一次网络请求；
  不缓存请求结果，写操作和切换身份后隔离旧请求，表单不会共享可变响应对象。
- 任务状态、已提交的新消息、产物合并成一个同步接口；使用消息序号增量拉取，
  避免每次重新发送整页历史。SSE 阶段事件不再逐个触发三组 HTTP 请求。
- 功能页面延迟加载；空闲侧栏降低轮询频率，回到窗口立即刷新。
- 提示词组装与历史读取/裁剪分离。每轮只查询有界历史，成对保留工具意图和结果，
  保留任务目标与最新补充，不修改数据库原始消息。
- 已读长正文可以缩为带 SHA、路径、来源地址等元数据的摘录；用 conversation_history
  按序号和偏移恢复原记录。模型不能把省略视为成功、失败或未发生。
- 常用和当前相关工具先进入模型请求，tool_discover 可以展开其他工具完整参数。
  目录缩减不改变权限；执行前仍使用最新策略检查。
- 技能先附名称、说明与建议，skill_use 加载后才保留完整指导；不会仅因关键词匹配
  就反复附上大型技能全文。已经加载的规则仍保留。
- 相同文本的向量有界缓存与并发合并，命中返回副本；数据库召回结果不缓存。
  没有有效记忆时不再请求向量服务。
- 独立的只读查询可以由模型在同一批次提出，减少模型回合；依赖上个结果的请求仍需等待。

TokenEstimate 只用于本地选择上下文，实际 Token 和费用仍以供应商 usage 为准。
不能为了降低数字而丢失用户约束、放宽权限、隐藏未知操作结果或伪称任务完成。

## 多个聊天模型

保存新配置、修改已有配置前，服务端自动验证实际的流式工具调用协议。
手动测试同样使用流式接口，检测 URL、Key、模型以及有效工具响应。
检测失败返回“配置未保存”，不新增、不覆盖，也不改变当前选择。
相同用户、地址、Key、模型的成功检测可在五分钟内复用；改变任一项会重新验证，
手动重测失败会撤销之前的验证结果。服务以整段返回时会明确提示其响应方式。

从输入框的模型菜单进入“管理模型”，点击“新增”。每份配置独立保存 URL、
Key 和模型名；配置名称可选，留空使用模型名。“保存配置”保留当前选择，
“保存并使用”同时切换。已有配置可以编辑、测试和删除，输入框菜单直接切换模型。
模型列表与当前选择保存在 PostgreSQL，重启应用后仍然保留。切回系统默认不会移除已保存配置。

V22 自动恢复旧版本已保存的服务地址和模型组合，保留原来的选中项；
同一服务、模型的反复保存合并为一条可见配置。旧版本记录仍供已启动任务读取。
每次编辑产生新的不可变配置版本，进行中或暂停的任务继续使用启动时的版本。
删除从可选列表移除配置，当前任务保留原版本；删除正在使用的配置后，新任务使用系统默认。
每份配置的 Key 独立加密，测试未选中的配置不会复用当前模型的 Key。

验证脚本 scripts/verify-saved-models.mjs 覆盖旧配置迁移、独立保存/选择、密钥归属、
运行中版本固定、过期编辑冲突及用户隔离；桌面脚本
agent-web/scripts/verify-saved-models.cjs 验证实际界面的新增、测试、保存、切换和重启保留。

## 暂停与继续

模型连接错误现在显示 HTTP 状态、连接中断、超时或协议异常。
重试间隔只取决于连续失败次数，不被之前成功的调用拉长。
连续三次失败会自动暂停并保存当前步骤；点击输入框的继续按钮后，
从同一任务继续，连续失败计数重新开始。这与正常长任务的调用额度分别处理。
Chat 的普通问题可直接流式给出正文；需要查询资料时仍可调用工具，
不会强制每个回答都通过 finish_task 返回。

输入框模式与任务绑定。点击输入框右侧的暂停按钮后：

- 正在生成回答时中断该次生成，未完成草稿不作为最终答案。
- 已开始的工具操作先结束并记录结果，再停在安全边界；不会强行终止在途写操作。
- 暂停状态、检查点保存在 PostgreSQL，重启应用或后端后仍可以继续。
- 暂停期间不启动模型/工具调用，任务超时暂停计时。
- 在底部同一个输入框填写补充，点击发送或按 Enter 继续；空白时点击按钮直接继续。
  沿用原任务 ID、计划、已完成结果和授权范围；未执行的旧意图撤销后重新决策。
- 继续请求有幂等编号，断线重试不会重复追加补充。结果未知的操作必须先核对。

## 更省 Token 的任务写法

优先说明目标、范围和验收办法，避免“把全部都看一遍”：

> 先用 Plan 检查登录模块，重点看鉴权和异常处理。只读必要文件，
> 最多列出 5 个有证据的问题，附路径和行号；不要修改。最后给修复计划和验收步骤。

确认后切 Build：

> 按这份计划执行，只修复已确认的问题。复用已读片段与已有发现，
> 独立读取可同批提出；每个阶段保存结论。完成后运行相关检查并展示差异，
> 不扩大到其他模块。

发现遗漏时，点击输入框右侧暂停，在同一输入框补充后发送：

> 保留已经完成的改动。补充要求：兼容现有接口，只修改登录模块；
> 数据库结构和部署配置先不要动。

简单问答或一次资料查询使用 Chat。不要反复粘贴整份已导入的文档、
整仓库代码或重复启动相同任务；优先给文件路径、关键词、知识库文档名。
