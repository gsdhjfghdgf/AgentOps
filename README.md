# AgentOps 智能体平台（单 Agent 企业级实现）

基于《Agent 设计与实现文档》（v1.2，35 节）持续完善的单 Agent 应用：

- **后端**：Java 17 + Spring Boot 3.5.16 + PostgreSQL 17(pgvector) + Redis，ReAct 执行循环、租约/检查点/幂等、预算与配额、工具批准（HITL）、SSE 事件流、RAG 知识库、长期记忆、任务级评测。
- **前端**：Electron + Vue3 桌面应用（Windows NSIS 安装包），暖白与低饱和绿的工作空间风格，支持深浅主题。

## 二、启动顺序（重要）

### 1. 启动 SSH 隧道（后端启动前置）

VM 内 Docker：`agent-postgres`（5432）、`agent-redis`（容器内 6379）。实测发现旧 Docker 的 `6380→6380` 映射不匹配实际监听端口。项目脚本每次通过 SSH 发现 Redis 容器地址，直接转发到容器内 6379，本地使用 16380 避开旧隧道。

```powershell
& 'D:\Agent实战\scripts\start-dev-tunnels.ps1'
```

脚本使用现有 `D:\VM\scripts\vm_key`，不读取或输出私钥正文；保留已有端口监听，不停止其他程序。脚本会在当前 PowerShell 设置 `SPRING_DATA_REDIS_PORT=16380`，后端需在同一个 PowerShell 启动。另开终端时先手动设置该环境变量。SSH 主机指纹必须已在 known_hosts 中受信任。

### 2. 启动后端

```powershell
cd D:\Agent实战\agent-server
mvn -q spring-boot:run -DskipTests
```

看到 `Started AgentServerApplication` 即就绪；Flyway 启动时自动迁移（V0-V22）。

### 3. 启动桌面端

开发联调（热更新 + DevTools）：

```powershell
cd D:\Agent实战\agent-web
npm run app:dev
```

直接运行打包前版本：

```powershell
npm run app
```

产出 Windows 安装包（`agent-web/release/AgentOps 智能助手-Setup-0.1.24.exe`）：

```powershell
npm run dist
```

> Electron 二进制走 npmmirror：环境变量 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`、`ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/`。

## 五、评测管线（builtin 套件 6/6 通过）

```powershell
# 先在桌面端创建账号，再用本人的账号登录；不把密码写入脚本或命令历史。
$credential = Get-Credential
$body = @{username=$credential.UserName;password=$credential.GetNetworkCredential().Password} | ConvertTo-Json
$login = Invoke-RestMethod http://127.0.0.1:8080/api/auth/login -Method Post -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body))
$H = @{Authorization='Bearer '+$login.accessToken}
# 1. 导入内置套件（6 用例：直接回答/销售查询/周报/RAG/模糊澄清/邮件批准）
$suite = Invoke-RestMethod http://127.0.0.1:8080/api/eval/suites/builtin -Method Post -Headers $H -ContentType application/json -Body '{}'
$suiteId = $suite.suiteId
# 2. 运行（同步返回报告；桌面端「评测」页同样可操作）
Invoke-RestMethod "http://127.0.0.1:8080/api/eval/suites/$suiteId/run" -Method Post -Headers $H -ContentType application/json -Body '{}'
# 3. 查询报告（用于回归对比）
Invoke-RestMethod "http://127.0.0.1:8080/api/eval/suites/$suiteId/report" -Headers $H
```

- 评分规则：normal 类要求 succeeded；ambiguous 类预期 `waiting_user`（澄清而非假设）；permission 类预期 `waiting_approval`（触发批准）。评测器在轮询中识别等待态并立即判定，用例结束后自动取消残留 run。
- 重复运行同一套件时 trial_no 自动递增（`eval_trials(case_id, trial_no)` 唯一键）。

## 六、账号与身份

- 使用注册、登录、退出、个人资料、密码管理与登录设备管理；首次从本机桌面端创建账号时，可明确接管旧工作空间，保留默认身份原有数据。
- 桌面端通过本机注册凭据完成账号创建，阻止普通网页通过空 Origin 抢先接管；该凭据由后端生成，只允许当前系统用户读取，不写入源码或日志。
- 登录使用可过期、可撤销的随机 Bearer 凭据。后端覆盖身份头，客户端填写的 `X-Tenant-Id` / `X-User-Id` 与 SSE 查询参数都不能作为授权依据。
- SSE 改为带 Authorization 请求头的 fetch 流，凭据不进入网址。桌面端记住登录使用系统加密，浏览器会话只在 sessionStorage 保存；不将密码或登录凭据放入 localStorage。
- 默认仅监听 `127.0.0.1`。跨主机部署需配置 HTTPS、精确允许来源及注册凭据分发，不能简单对外暴露调试端口。详见 [账号与安全设计](docs/账号与安全设计.md)。

## 八、常见问题

- **`RedisConnectionException` 或健康检查 DOWN**：运行项目的 `scripts/start-dev-tunnels.ps1`，确认后端同一终端中的 `SPRING_DATA_REDIS_PORT` 为 `16380`。旧脚本把 Redis 转发到未监听的容器 6380，不能仅靠重复启动旧脚本恢复。
- **后端启动报 Flyway 迁移失败**：检查 `agent-server/target/classes/db/migration` 是否含最新 V*.sql，并查看 Flyway 错误日志。已应用的迁移保持不变，数据库变更通过新增迁移完成。
- **桌面端顶栏显示「后端离线」**：后端未启动或 8080 被占用；先启动 agent-server。
- **创建 run 返回 409**：同会话同时只允许一个未结束任务（文档 16.3 单飞约束）。

## 九、本轮功能完善（2026-10-27）

- 会话恢复：重新打开或切换会话后，自动恢复未结束任务、待批准操作和补充问题；顶部可选择最近 100 个任务，查看状态和产物。
- 历史消息：按时间正序显示，支持游标加载更早消息，加载后保留已有消息和滚动位置；工具调用参数单独展示。
- 流式回答：订阅 `message.delta`，按动画帧缓冲播放，生成中的文字明确标记为待校验；任务终态以后端状态为准。
- SSE 重连：优先读取浏览器的 `Last-Event-ID`，按持久化事件顺序分页重放；失效游标返回 `run.snapshot`，终态无剩余事件也会发送状态快照；连接关闭后释放后台读取任务。
- 产物恢复：任务列表切换后可重新查询可下载的报告，下载时优先使用 UTF-8 文件名。
- 提交与状态一致性：新任务使用独立请求键，断线重试复用请求键；服务端哈希覆盖完成契约，任务创建串行校验会话归属和单任务约束。
- 输入与取消：补充输入绑定当前问题编号，消息、命令和重新入队同事务提交；排队和等待输入/批准的任务可立即取消，运行中的操作采用协作取消，结果未知的任务仍等待核对。
- 审批隔离：查询和决策包含用户归属过滤；已结束、取消或超时的任务拒绝迟到批准，审批和任务推进同事务提交。事件订阅者只在事务成功提交后收到通知。

## 十、会话管理与运行中补充（0.1.2）

- 侧栏支持标题搜索、重命名、置顶、归档/恢复、单条删除及清空当前账号会话。时间按本机时区显示；首条请求自动生成标题。
- 评测会话有独立类型，历史评测按实际任务契约迁移分类，后续评测不混入日常会话列表。
- 删除采用会话逻辑删除，历史入口不再展示；清空不删除知识库、长期记忆或评测结果。有未结束任务时先停止任务再删除。
- 正在排队、执行或等待重试时可以发送补充要求。补充请求使用稳定命令编号持久化并去重，显示已接收/已应用回执；完整工具批次结束后进入模型决策时应用，已有步骤不重置。
- 成功提交事务检查未应用的补充要求，避免任务在新要求尚未处理时误报完成。当前工具调用期间的补充会等待工具批次结束；已派发的外部操作无法承诺撤销。
- 停止任务会立即登记取消状态，执行控制读取数据库取消标记；执行过程可展开查看阶段、工具、批准、补充及终态事件。
- 新增 Flyway V9 迁移，只增量添加字段和命令类型。先启动更新后的后端，再安装新版桌面端。

## 22. 重复读取保护与阶段发现（0.1.15）

项目读取从每次1800字符提高至6000字符，返回起止行号、字符区间、SHA256和明确的eof。eof=true表示已到文件末尾。项目读取工具返回上限同步提高，防止较大中文片段被截成无效JSON。

按账号、任务、路径、SHA256与区间保存已读台账，显示实际读取、不同片段与重复次数。同一文件内容变化后使用新SHA，算新进展；不同区间也不算重复。task_notes保存最多6000字的阶段发现、文件证据和剩余事项，系统提示要求每5～10次读取或确认新发现时更新。笔记与最近已读台账会进入后续模型上下文，避免历史裁剪后从头扫描。

保存阶段笔记后，已经覆盖的旧项目读取结果在后续模型输入中压缩为路径、区间、SHA和说明；尚未覆盖的新读取仍保留正文。数据库中的原始工具结果不改写，可以继续核验证据。笔记是Agent的阶段记录，不是已完成测试的证明，也不增加工具权限。

同一版本的重复片段连续累计4次、其间没有读到新片段或记录新发现时，系统提示改变策略并先整理结论；累计12次则在下一次付费模型调用前进入等待用户状态，显示“整理已有发现并结束”和“继续深入检查”选项。回答后在同一任务继续并重置该计数。它是可继续的重复读取保护，不以任务时长或文件数量限制正常长任务，也不是所有类型循环的通用检测器。

运行条新增已读文件、读取次数、不同片段与重复次数，以及可展开的阶段发现。旧版任务只能按历史调用参数做回溯统计，会标为“不同读取参数”；新版台账不补造旧任务的阶段结论。累计Token说明明确包含每次模型请求的输入与输出及重复上下文，不表示最终答案的长度。

侧栏头像、名称、“更多”与右上角用户图标统一打开个人设置弹窗。支持本机显示名称、外观和聊天模型入口；保存名称或外观保留当前会话。清空会话改为明确入口并再次确认，“更多”不再直接触发删除。支持关闭按钮、遮罩、Esc、Tab焦点约束及关闭后恢复焦点。Tenant/User UUID移入默认收起的开发者设置，先验证格式；切换数据视图不会删除已有数据或停止原工作空间任务。此处是本机资料设置，不是生产登录系统。

实际模型任务使用OpenAI兼容SSE请求：逐段解析公开content与finish_task.answer，实时发送到桌面端；reasoning_content不进入界面、事件或消息记录。公开说明、工具过程、成功保存的task_notes阶段发现与最终回答按时间排列，模型未提供说明时给出简短的下一步行动提示。阶段发现是Agent记录，不代表问题或测试已被独立验证，可展开工具结果核对原文。

工具调用参数在完整结束且JSON合法后才提交给引擎；分段参数不会提前执行。中文、JSON转义和表情跨分段拼接，末尾usage用于记录Token。支持不理会stream参数而返回完整JSON的服务，但这类服务无法提供真正的逐段显示，界面不伪造打字效果。仅提供普通文字、没有工具调用能力的模型仍不能运行Agent任务。

每次模型调用有独立attemptId，开始、分段、提交和中断事件用于重连去重及恢复。收到已保存消息后移除对应临时输出；重试不混入上次的草稿，重新打开会话读取持久化结果。生成中的回答标为待校验；被取消或截断的草稿不作为最终答案保存。停止请求会主动关闭上游流连接，并清除中断标志后进行数据库收尾；已发出的模型请求可能计费，缺少最终usage时保守记录，模型用量未知不等于有外部工具副作用需人工核对。

## 24. 网页搜索相关性与原文核验（0.1.17）

移除“必应RSS只要非空就采用”的旧路径，改用必应网页、360、搜狗三源并发检索。保留完整查询，按完整主体、引号短语和site域名限定筛选，按关键词覆盖与标题匹配排序；机构和新闻站点仅作小幅排序参考，不代表其内容已经核实。合并原始链接和搜索源，去掉常见跟踪参数、翻译框及搜索页面本身；必应和DuckDuckGo的可解码跳转链接还原为原始地址，360优先取原始链接字段。最多返回8条候选，附检索时间、原始日期标签、匹配词、各搜索源状态和过滤数量。20秒总等待预算、独立并发上限和取消检查避免单一搜索源无限阻塞。

相关性筛选是保守的字面匹配，不是语义或事实确认。某些搜索引擎仍可能忽略查询条件、包含旧索引或改版链接。无结果明确标记no_relevant_results，部分源超时或阻断会说明覆盖有限；不能据此判断事件没有发生。官网资料只命中博客、首页或不支持当前问题的正文时，应保留完整主题并用已确认的官网域名限定后再次检索，而不是把平台域名或转载数量当作证明。

web_read识别HTTP失败、空页、薄内容与验证页，返回unavailable/empty/thin_content/blocked，保留实际来源并说明未取得有效正文。使用[Jsoup的元素选择和文本提取](https://jsoup.org/apidocs/org/jsoup/nodes/Element)处理文章、主内容和Markdown容器，避免把页尾推广article误当正文；按HTTP或HTML声明解码UTF-8/GBK/GB18030，提取实际提供的作者、日期和JSON-LD articleBody，保留段落及截断标记。无法静态读取的动态页面可由Agent在当前工具权限范围内调用browser_open；不绕过验证码、不自动扩大授权，来源未提供日期时不补造。

对话新增可展开的来源列表：标题、域名、摘要、日期标签、检索时间和原文链接，并标记“待核对原文”。旧版历史仅展示原有来源，明确未使用新版筛选；不会改写旧回答。全局提示和内置web-research技能要求人物生死、健康及最新事件先核对原文，区分原始公告、可靠报道、平台用户号与转载；无证据不等于谣言，也不能据此宣称已确认平安。联网继续按任务授权一次，搜索和不同网页读取共用授权。

## 25. 执行过程统一折叠（0.1.18）

每次任务的公开行动说明、工具调用、搜索来源、阶段发现、补充记录及运行日志放入同一个“执行过程”折叠区，摘要显示用时与操作数量。运行时默认展开，用户手动收起后，新记录和状态刷新不会强制展开。最终回答的首个流式分段到达，或最终候选正文保存时，自动收起执行过程；最终正文始终位于折叠区外，完成后仍可手动展开历史。重新打开已完成会话时默认收起。先前被后续执行或补充要求取代的候选正文保留在过程内，不冒充当前最终答案。
